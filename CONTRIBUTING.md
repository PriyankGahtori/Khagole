# Contributing

Thanks for your interest in khagole-engine! Bug reports, fixes, documentation and
ports of missing features are all welcome.

## Reporting bugs

- **A chart value looks wrong?** Open an issue with the complete request (UTC moment,
  latitude, longitude, house system, zodiac type, ayanamsa, orb settings if any), the value
  the engine returns, the value you expected, and where the expected value comes from
  (another program, an ephemeris, a published table).
- **A crash, or an error you did not expect?** Include the version, the binding (Rust,
  Python, WebAssembly), the platform and a minimal reproducer.
- **A security issue?** Do not open an issue. See [SECURITY.md](SECURITY.md).

## Setup

- Rust ≥ 1.85 (the MSRV, also tested in CI) via [rustup](https://rustup.rs).
- The full JPL kernel: `scripts/fetch-kernels.sh` downloads `kernels/de440s.bsp` (~32 MB,
  gitignored). Without it the tests use a committed one-year excerpt, and **the golden
  chart tests silently skip** (they print "skipping" and pass). A green run without the
  kernel does not validate charts.
- For the Python bindings: Python ≥ 3.12, a virtualenv, `pip install maturin pytest`.
- For the WebAssembly bindings: `rustup target add wasm32-unknown-unknown`,
  [wasm-pack](https://rustwasm.github.io/wasm-pack/) and Node.js.

## Everyday commands

```bash
cargo test --workspace --exclude khagole-engine-py     # fast: committed excerpt
cargo test -p khagole-engine --release                 # with the kernel: golden + full range
cargo fmt --all && cargo clippy --workspace --all-targets -- -D warnings
RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps

# Targets the apps depend on must keep compiling
cargo build -p khagole-engine -p khagole-engine-wasm --lib --target wasm32-unknown-unknown
cargo check -p khagole-engine --lib --target aarch64-linux-android   # and aarch64-apple-ios

# Python bindings (in a virtualenv)
maturin develop -m crates/khagole-engine-py/Cargo.toml
pytest crates/khagole-engine-py/tests

# WebAssembly bindings
wasm-pack build --target nodejs --out-dir pkg-node crates/khagole-engine-wasm
node crates/khagole-engine-wasm/tests/golden.mjs

# Landing site with the live demo, served at http://localhost:8000
scripts/build-site.sh && python3 -m http.server -d target/site
```

The Python crate is excluded from `cargo test` because it links against libpython. Test it
through maturin.

Tests that need `kernels/de440s.bsp` print "skipping" and pass when it is missing. Set
`ASTROCELESTE_REQUIRE_KERNEL=1` to make that a failure, as CI does. For a performance
change, compare `cargo test --release --test timing -- --ignored --nocapture` before and
after.

[docs/architecture.md](docs/architecture.md) explains how the code is organised.

## Correctness first

The engine is a port of the Khagole reference implementation (Python on Skyfield), and
every number it produces is checked against a reference:

- `tests/fixtures/{natal,horary,transits,synastry,derived,errors}.json`: complete charts
  from the reference implementation. These fixtures are the acceptance spec. The engine
  must reproduce them with floats within 1e-9, the same key order and the same int vs
  float number types.
- `tests/fixtures/spk_reference.json` and the `tests/data/de440s_2000.bsp` excerpt: raw
  kernel states from `jplephem` (`scripts/make_spk_fixtures.py`).
- `tests/fixtures/reduction.json`: stage-by-stage reduction values from Skyfield
  (`scripts/make_reduction_fixtures.py`).
- `tests/fixtures/ziwei_iztro*.json`: Zi Wei Dou Shu charts from
  [iztro](https://github.com/SylarLong/iztro) (`scripts/make_ziwei_*fixtures.cjs`).

A change that moves any fixture value must explain why the new value is more correct, and
regenerate the fixtures in the same pull request.

When porting reference code:

- Use `pyfloat.rs` (`rem`, `floordiv`, `divmod`, `round`, `round_int`) wherever the
  reference uses Python's `%`, `//` or `round()`. Rust's `%` and `f64::round` differ at
  the boundaries, and the difference moves signs and orbs.
- Serialize integers and floats exactly as the reference does.
- Keep the module doc comment naming the reference function it ports (for example
  `SkyfieldEngine.calculate_planets`).
- The embedded tables (`src/data/*.bin`, `src/frames/nutation_data.rs`) are generated by
  `scripts/gen_tables.py`. Do not edit them by hand.

See [docs/accuracy.md](docs/accuracy.md) for the full picture.

## Public API

- The API is curated in `lib.rs`: modules are private, and entry points and every type
  reachable from a result are re-exported. A new result type must be added there.
- `missing_docs` is enabled and CI denies warnings: every public item needs a doc comment.
- Public enums that may grow (`EngineError`, `SpkError`, `HouseSystem`) are
  `#[non_exhaustive]`.
- A change to the bindings updates the Python type stub (`khagole_engine.pyi`), the
  binding READMEs and both binding test suites.

## Dependencies and portability

The engine ships inside closed-source applications and in the browser, so it stays
dependency-light (the core depends only on `serde` and `serde_json`) and permissively
licensed (`deny.toml`, checked by cargo-deny in CI). It must keep building for
`wasm32-unknown-unknown`, Android and iOS: no C code and no platform-specific I/O in the
core.

## Commits and pull requests

Use [Conventional Commits](https://www.conventionalcommits.org). `release-plz update`
derives the version bump and the changelog from them:

```text
feat: add the true lunar node
fix(houses): Placidus cusps above the polar circle
docs: explain kernel excerpts
feat: rename ChartRequest::zodiac_type
```

The version stays at 0.0.x while the engine is experimental, and any release may change
the API. Do not mark commits as breaking (`!` or a `BREAKING CHANGE:` footer): release-plz
would bump the minor version. Say what changed for callers in the commit body instead.

Keep each pull request to one logical change. Before opening it, check that:

- [ ] `cargo fmt`, `clippy -D warnings` and `cargo doc` are clean;
- [ ] the tests pass **with the full kernel** (`scripts/fetch-kernels.sh`);
- [ ] binding changes are tested through maturin and wasm-pack;
- [ ] any fixture change is explained and regenerated in the same pull request;
- [ ] docs (rustdoc, READMEs, `docs/`) match the change.

Maintainers release by pushing a version tag: see [RELEASING.md](RELEASING.md).
